# Boot runtime consumers: no supported 400 MiB difference found

Read-only audit on September 9, 2026, covering volatile journals, retained initramfs, early kernel logging, and tmpfs. **None supplies a dated May-only RAM consumer in the retained evidence.** Current readings also rule out these mechanisms consuming hundreds of MiB now. Historical boot readbacks are missing, so this is a narrowing result rather than proof of identical May runtime state.

The installed `journald.conf(5)` documentation states that default `Storage=auto` uses persistent storage when `/var/log/journal` exists, starts with volatile storage during early boot, and switches on flush. The installed `systemd-journal-flush.service` issues that flush automatically. The timestamps above verify that it actually happened on this boot rather than merely relying on configuration intent.

The current command line contains neither retained-initrd/debug-break options nor a log-buffer-size override. Searches of readable GRUB/initramfs/journald configuration and all three retained shell histories found no `retain_initrd`, `keepinitrd`, `rd.break`, `log_buf_len`, journal storage switch, or manual tmpfs mount explaining the May-to-now difference. The retained shell initramfs command is an ordinary conditional creation if the requested kernel's image does not exist; it is not a keep-initrd setting.

Privileged `journalctl -u systemd-journald` for May 1–June 24 returns no entries. The retained system journal boot list begins September 7, so **May journal storage/flush success cannot be checked directly**. We must not interpret the missing entries as evidence that May journald failed. [Existing boot log inventory](kernel_memory_logs.json) records that retention limit and current initrd-free messages.

Evidence was read from `/proc/meminfo`, `/proc/cmdline`, `/proc/mounts`, filesystem allocation counters and metadata, installed kernel configurations, installed systemd/initramfs scripts/manuals, and focused read-only privileged journal/directory queries. No workload, cache drop, mount, journal flush, or host-setting change was performed.
